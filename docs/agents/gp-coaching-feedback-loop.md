# GP Coaching Feedback Loop

**Owner:** GP (grind-platform)  
**Mentor:** FP (forge-platform)  
**Last updated:** 2026-02-23

---

## Evidence Submission Cadence

GP submits evidence to FP after completing each Delivery or Improvement lane task. Evidence is a brief summary posted as a message to `inbox-FP` with:

- Task ID
- What was done
- Verification result (command + output)
- Self-rating: Meets Bar / Needs Work / Exceeds Bar

## Evidence Categories

| Category | Examples | Frequency |
|----------|---------|-----------|
| Delivery | RP5 fix committed + verified, publish triggered | Per task |
| Improvement | Risk register, runbook matrix, SOP doc | Per doc |
| Skill | Postmortem write-up, risk communication drill | Per drill |

## Recording Feedback

After FP replies:
1. Note FP's rating (pass/flag/fail) in this file under `## Feedback Log`.
2. If flagged: add action item to `todos` table with status `pending`.
3. If failed: block next skill task until remediated, post notice to inbox-GP.

## Promotion Criteria (from FP directive)

FP assesses, Marcus decides. GP earns promotion signals by:
- Zero post-review findings on 5 consecutive Delivery tasks
- Two passing Improvement lane tasks rated "Meets Bar" or above
- One Skill task rated "Exceeds Bar"

GP does NOT self-promote. All promotion decisions belong to Marcus.
