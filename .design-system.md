## 1. Brand Concept

**Name:** Motor City Math

**Design inspiration:** Detroit Pistons brand language — bold, confident, physical. This isn't a gentle pastel ed-tech app. It's a study tool with attitude, built by a dad who treats his son's grades the way Detroit treats basketball: seriously, with grit, and with zero excuses.

**Pistons context:** Cade Cunningham's breakout All-Star season, Jaden Ivey's comeback, a 30-win improvement — the Pistons rebuild is a parallel to Kai's grade trajectory. From struggling to dominant. That's the energy.

**Tagline options:**
- "Put in the work."
- "No shortcuts. Just reps."
- "Grind. Learn. Win."

**The story:** Marcus built 12 HTML practice tests and helped Kai go from struggling to earning an A in Algebra II at Seattle Academy (SAAS). Now we're building the system that makes that repeatable — adaptive tests, spaced repetition, per-standard tracking — all powered by a 6-agent AI team.

**School context:** Seattle Academy of Arts & Sciences (SAAS). Cardinals mascot, red/black/white school colors. Standards-based grading. Mission: Question, Imagine, Create, Contribute. The tests already reference SAAS standards (3.a, 3.b, etc.).

---

## 1b. ADHD Design Constraints *(Mash-approved)*

Kai has ADHD. Every screen must respect three principles:

1. **Focus over features** — During tests, show only the question, input, and timer. Hide everything else. No sidebar, no nav, no unrelated CTAs.
2. **Encourage over evaluate** — Use coach tone ("You nailed 12 out of 15") not clinical ("Score: 80%"). Max 12 words per feedback line.
3. **One thing at a time** — Reduce choices to prevent decision paralysis. One CTA per screen. Progressive disclosure on dashboard — show overview first, drill-down on tap.

**Hard rules:**
- Timer shows time *remaining*, not elapsed
- Show progress position ("Question 5 of 20") always visible
- No walls of text — ever
- Feedback copy must be ≤ 12 words

## 3. Typography

Keep the current Helvetica Neue stack — it's clean, universal, and doesn't need a CDN.

```css
font-family: 'Helvetica Neue', Helvetica, Arial, sans-serif;
```

### Type Scale — Locked 6-Step *(Mash-approved)*

Replaces 22+ ad-hoc sizes across the site with a strict modular scale.

| Token | Size | Weight | Use |
|-------|------|--------|-----|
| `--text-2xl` | 40px (2.5em) | 700 | Page titles (h1) |
| `--text-xl` | 28px (1.75em) | 700 | Page subtitles, section headers (h2) |
| `--text-lg` | 20px (1.25em) | 600 | Question numbers, emphasis |
| `--text-base` | 16px (1em) | 400 | Body text, questions, inputs, feedback |
| `--text-sm` | 14px (0.875em) | 600 | Labels, secondary text |
| `--text-xs` | 12px (0.75em) | 400 | Captions, chart labels, footnotes |

### Typography Changes from Current

- **h1 weight:** 400 → **700**. The Pistons brand is bold. Thin headers feel tentative.
- **Question number color:** burgundy → **pistons-blue**. Separates numbering from accent color. Creates a two-tone system (red for brand, blue for navigation).
- **Add letter-spacing: 1px** to question numbers (already uppercase — reinforce the Pistons' all-caps geometric style).

## 6. Iconography & Motifs

### Pistons-Inspired Visual Elements

- **Scoreboard aesthetic:** Score displays should feel like arena scoreboards — big numbers, bold type, dark backgrounds.
- **Stripe accent:** Thin horizontal stripe (red-blue-red) as a recurring divider motif. Mirrors the jersey stripe pattern.
- **Basketball iconography (subtle):** 🏀 emoji for streaks or milestones, not as decoration. The brand is sports-adjacent, not sports-themed. It's a study tool first.

### Streak & Progress Motifs

- **🔥 streak counter** — "5 correct in a row" with fire emoji
- **🏀 milestone markers** — "10 questions answered", "First perfect section"
- **⭐ mastery indicator** — Stars for standards fully mastered

### Feedback Copy (voice)

**Voice:** Marcus's own voice — direct, coaching, loves his son, pushes hard. See `.voice-guide.md` for the full reference. Kai has ADHD so copy must be clear, short, and motivating — never wordy.

Match the Pistons campaign energy — "Detroit Basketball. All The Time." becomes the study equivalent:

| State | Current Copy | New Copy |
|-------|-------------|----------|
| 90%+ score | "🌟 Excellent!" | "🔥 Nothing but net." |

| 70-79% | "✓ Good!" | "📈 Getting there. Run it again." |
| Below 70% | "📚 Keep practicing!" | "🏀 Back to the gym. You got this." |

## 8. Math Rendering

**Decision: Standardize on KaTeX** (not MathJax).

| | MathJax | KaTeX |
|-|---------|-------|
| Render speed | ~500ms | ~50ms (10x faster) |
| Bundle size | 1.2MB | 200KB |
| Visual quality | Excellent | Excellent |
| Offline | Needs CDN or big local copy | Smaller local footprint |

Current state: 4/12 files use MathJax, 8 use plain text. Moving to KaTeX everywhere gives fast rendering with clean LaTeX notation for all equations.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/katex@0.16/dist/katex.min.css">
<script src="https://cdn.jsdelivr.net/npm/katex@0.16/dist/katex.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/katex@0.16/dist/contrib/auto-render.min.js"></script>
```

- "Your Game Plan 🎯" — standards breakdown + study recommendations

## 11. Dark Mode ("Arena Mode" 🏟️) — v3.0 Updated

Optional dark theme that mirrors the arena/scoreboard vibe. Toggle persists across pages via localStorage.

### Persistence Pattern *(implemented)*

```html
<!-- In <head> of EVERY HTML file — BEFORE CSS renders (prevents flash) -->
<script>if(localStorage.getItem('mcm-arena-mode')==='on')document.body.classList.add('arena-mode');</script>
```

```js
// In toggle handler (shared/scripts.js)
localStorage.setItem('mcm-arena-mode', isArena ? 'on' : 'off');
```

**Key:** `mcm-arena-mode` (values: `'on'` / `'off'`). Blocking script in `<head>` ensures no flash-of-wrong-theme.

## 16. Accessibility Patterns (Sprint 4 additions)

### 16a. Reduced Motion

All animations must respect `prefers-reduced-motion`. Pattern:

```css
@media (prefers-reduced-motion: reduce) {
  .animated-element { animation: none; }
}
```

For JS-driven animations with delays, check in JS:
```js
var prefersReduced = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
if (!prefersReduced) { /* run animation */ }
```

Applied in: `exam.html` score reveal (line 1086), `correct-pulse` spec.

### 16b. Form Label Association

All `<label>` elements MUST use `for="inputId"` to programmatically link to their input:

```html
<!-- CORRECT -->
<label for="q1a">Slope:</label>
<input type="text" id="q1a">

<!-- WRONG -- label is decorative, screen reader cannot link it -->
<label>Slope:</label>
<input type="text" id="q1a">
```

Applies to all input types: text, number, dropdown (select), radio groups.
Radio option labels are ALSO correct via `for/id` pair per-option.

### 16c. Aria-Label String Format Rule

When writing aria-label specs, always provide the exact string template, not just semantic intent.

**Why:** Vague intent ("describe what this displays") leads to complex string concatenation in inline HTML.
Complex string concatenation = SyntaxError risk (caused P1 score display outage, commit 6bd2ee6).

**Pattern:** Prefer simple, non-concatenated formats:
- Good: `aria-label="W1.a: 82%"`
- Risky: `aria-label="Standard W1.a: 82% correct (3 of 4 attempts)"`

When concatenation is unavoidable, keep variable references to one per string.

### 16d. Scorecard Progressive Disclosure

Two-phase scorecard: let the score land before showing breakdown.

Phase 1 (immediate): score big + grade letter + coach message (12 words max) + "See Game Plan" button
Phase 2 (on demand): standards grid with per-standard results, revealed via button press

```js
function revealGamePlan() {
    document.getElementById('gamePlanSection').style.display = '';
    var btn = document.getElementById('gameplanBtn');
    btn.textContent = 'Game Plan ✓';
    btn.disabled = true;
    btn.setAttribute('aria-pressed', 'true');
}
```

Rationale: ADHD attention is disrupted after a test. One signal at a time. The number lands first.
Button gives Kai control over when he is ready for the detail view.

### 16e. Position Tracker

For exams with multiple questions, show a sticky position indicator:

```html
<div id="questionTracker" style="display:none" aria-live="polite" aria-label="Question position"></div>
```

CSS: `position: sticky; top: 0; text-align: right; color: var(--text-secondary);`
Content: `"Q3 of 15"` updated via IntersectionObserver as Kai scrolls.
Hide when: exam has 1 question, picker mode, or after gradeExam() runs.

### 16f. Color + Non-Color Rule (WCAG 1.4.1)

**MCM must always pair color-based state changes with a non-color indicator (text, icon, or shape).**

Color = fast visual signal for sighted users.
Text + icon = accessible fallback for color-blind users and screen readers.

Audit finding (Feb 2026): correct/incorrect input border colors FAIL under deuteranopia, protanopia, and tritanopia simulation (1.76-3.69:1 on dark bg). MCM passes WCAG 1.4.1 only because text feedback + emoji (✅ ❌) are always shown alongside border changes.

**Rule:** Never remove the text/emoji feedback from grading. If a design removes text feedback for minimalism, it must add a shape-based indicator (icon, pattern, or form element change) instead.

### 16g. Focus Ring: Never Override with Hard-Coded White

The shared `shared/styles.css` defines the correct focus ring for both light and dark mode:
```css
:focus-visible {
    outline: 3px solid var(--accent-blue-on-dark);
    outline-offset: 2px;
}
```

**Do NOT override `:focus-visible` in page-level `<style>` blocks with a hard-coded color.**

Bug pattern (Feb 2026): `exam.html` had an inline `:focus-visible` rule with `rgba(255,255,255,0.9)` (white). This was visible in dark/arena mode but invisible on `--bg-card: #FFFFFF` in light mode. The inline rule overrode the shared rule because it loaded later in the cascade.

If a page needs a custom focus color (e.g., on a colored button), scope it to that element:
```css
.btn-primary:focus-visible { outline-color: white; } /* scoped, not global */
```
Never set a global `:focus-visible` that bakes in a specific color without testing both light and dark mode. Use `var(--border-focus)` as the fallback token when a custom color is needed.

### 16h. Grade Badge Contrast: Dark Text for Light Backgrounds in Dark Mode

Grade badges (`.saas-grade`) use `color: white` for all levels. In light mode this passes because badge backgrounds are dark (navy, deep green, deep red). In arena/dark mode, some badge colors lighten significantly.

**Rule:** When `--color-correct` is a light green in dark mode (e.g., `#2ECC71`), white text fails (2.07:1 on this value). Use `var(--color-correct-bg)` (dark green) as the text color instead.

Pattern for dark-mode badge overrides:
```css
body.arena-mode .saas-grade.g4 { color: var(--color-correct-bg); }
/* dark green on light green = ~8.5:1 PASS */
```

Always verify badge contrast in BOTH light and dark mode before shipping grade display changes.
